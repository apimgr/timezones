# Implementation status

`AI.md` is the implementation source of truth and `IDEA.md` defines the product scope. This status summarizes the current tree; it is not a claim of full compliance.

The service embeds timezone records and web assets, provides versioned REST lookup endpoints with response envelopes and pagination, a server-rendered homepage and server pages, theme preferences, and the `timezones-cli` binary. It also serves a GraphQL endpoint and explorer, a bundled Swagger UI, an OpenAPI JSON description, current-time views, and robots, sitemap, Atom, RSS, security.txt, and llms.txt discovery resources.

The implementation remains incomplete against the full AI.md baseline. Verified remaining work is tracked in [TODO.AI.md](TODO.AI.md). Major gaps include the broad server configuration and lifecycle baseline, authentication/MCP, the required server/client CLI behavior, complete localization integration, security disclosure/contact workflows, and full platform integration. Provider workflow files and i18n catalogs are now present, but have not yet had their required final workflow/browser verification. The required security and contact handlers remain unimplemented. IDEA.md follows AI.md's public-read and protected-operation access model.

Three inputs are awaiting the coordinating session: the exact stable `owner_token` cookie/localStorage name required by AI.md before token UI implementation; the supported-release policy; and security response-time wording for `.github/SECURITY.md`. These values have not been guessed. The timezone dataset's provenance and redistribution terms are verified against an exact source-file match at the pinned upstream commit and recorded in `LICENSE.md`.

Current verification: wrapped `make test` passes with 70.1% coverage; wrapped `golangci-lint run ./...`, `shellcheck tests/incus.sh tests/docker.sh tests/run_tests.sh`, and `mkdocs build --strict` pass. Go sources were formatted with gofmt in the Go container, and shell scripts with shfmt. The required Docker/Incus, browser, workflow, and release checks have not yet been run against the current edits. Historical Docker/browser smoke results predate these changes and do not verify the current tree.
