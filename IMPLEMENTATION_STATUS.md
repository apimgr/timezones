# Implementation status

`AI.md` is the implementation source of truth and `IDEA.md` defines the product scope. This status summarizes the current tree; it is not a claim of full compliance.

The service embeds timezone records and web assets, provides versioned REST lookup endpoints with response envelopes and pagination, a server-rendered homepage and server pages, theme preferences, and the `timezones-cli` binary. It also serves a GraphQL endpoint and explorer, a bundled Swagger UI, an OpenAPI JSON description, current-time views, and robots, sitemap, Atom, RSS, security.txt, and llms.txt discovery resources. `/server` permanently redirects to `/server/about`. The README, API/security docs, and all six locale catalogs now describe unsupported token, MCP, and metrics features accurately.

The implementation remains incomplete against the full AI.md baseline. Verified remaining work is tracked in [TODO.AI.md](TODO.AI.md). Major gaps include the broad server configuration and lifecycle baseline, authentication/MCP, the required server/client CLI behavior, complete localization integration, security disclosure/contact workflows, and full platform integration. Provider workflow files and i18n catalogs are now present, but have not yet had their required final workflow/browser verification. The required security and contact handlers remain unimplemented. IDEA.md follows AI.md's public-read and protected-operation access model.

Two inputs are awaiting the coordinating session: the exact stable project-specific `owner_token` cookie/localStorage name required by AI.md before browser token storage is implemented, and the supported-release and security response-time policies for `.github/SECURITY.md`. Messages to the coordinating API session have been rejected by its active-writer lock, so the questions remain unanswered and the values have not been guessed. The timezone dataset's provenance and redistribution terms are verified against an exact source-file match at the pinned upstream commit and recorded in `LICENSE.md`.

Current verification: wrapped `make test` passes with 70.2% coverage; wrapped Docker-toolchain `golangci-lint run ./...` reports zero issues; wrapped ShellCheck passes for all four test scripts; the E2E Go package compiles with its browser build tag; strict MkDocs build, YAML parsing, `shfmt -d`, and `git diff --check` pass. The prescribed Docker-tier script previously exited before reporting checks; its output suppression was removed, but the test gate rejected standalone script invocation, so it has not been rerun. Incus and full browser E2E runtime suites, actionlint/provider workflow checks, and release checks remain unverified. Historical Docker/browser smoke results predate the current edits and do not verify the current tree.
